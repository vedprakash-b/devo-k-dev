# ADR-041: The provider adapter talks HTTP directly with httpx and streams every call, instead of using the openai SDK

- **Status:** Proposed
- **Date:** 2026-10-26
- **Deciders:** Ved

## Decision

The provider adapter talks HTTP directly with httpx and streams every call, instead of using the openai SDK.

## Why

The router needs raw status codes, error bodies, rate-limit headers and first-token timing on every call, and must decide retries itself; the SDK hides some of these and retries on its own. Streaming is what makes a hung call detectable. httpx's transports also make the adapter testable without keys.

## Revisit if

A provider requires a feature that is only practical through its SDK.

## Details

Refines ADR-004, whose design text said "the official openai SDK and httpx". See `src/devokdev/llm/adapter.py`. The walkthrough with alternatives and trade-offs is in [`docs/learning/M1.md`](../learning/M1.md).
